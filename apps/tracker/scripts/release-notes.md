# Writing release notes for the ELEVATE Tracker App

HR writes these in ELEVATE (Settings > ELEVATE Tracker > Releases > New release), not in this file. Use this page as a guide.

People read them on the download page and in the "What's new" box the app shows once after an update. Write for a contractor, not a developer.

## The three lists

- **Added**: something new a person can now do. "Pick a client or project when you clock in."
- **Improved**: something that already worked and is now better. "The window opens faster."
- **Fixed**: something that was wrong and is now right. "The last picture now shows right after it is taken."

## Rules

- One short sentence per change, in plain English, starting with what the person sees. No version numbers, file names or technical words.
- Never mention a person, a client, a screenshot's content or an app name.
- If a release changes what the app records or collects, tick "Adds data collection" in ELEVATE and choose the monitoring policy version that covers it. ELEVATE will not publish it otherwise.
- Tick "Required update" only when old versions must stop working (for example a security fix). Old versions then stop sending until they update; hours are never affected.
- A bad release is withdrawn, never deleted. Publish the fix as a new, higher version.

## Example

Added
- Pick a client or project when you clock in, and switch while you work.

Improved
- The tray menu shows only the clock actions that fit what you are doing.

Fixed
- The Break menu no longer disappears on small screens.
