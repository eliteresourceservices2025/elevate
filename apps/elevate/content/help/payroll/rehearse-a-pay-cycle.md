A **test run** is a practice pay run. You can take a real earlier period, fill it from the real Jibble file, check the pay, make the payment list, read every statement and make the client invoice, and none of it reaches a contractor or uses a real invoice number. When you are done you archive it. All names and amounts in this guide are made up.

# Before you start

- Use test runs with real figures only in the live ELEVATE, and only after the privacy notice has been published. Never put real pay figures in a practice copy of ELEVATE.
- You need a payroll level: a **Preparer** builds and fills the run, an **Approver** approves it and releases statements. Both can download the payment list. A person cannot approve a run they prepared or changed.

# The steps

1. **Start the run.** Open **Payroll**, then **New run**. Tick **This is a test run**. A test run can use any earlier dates (up to 31 days): a whole cutoff, part of a cutoff, or exactly the dates of a Jibble file. It may repeat a period that already has a run.
2. **Fill it in.** Use **Fill or update this run**, then **Import Jibble timesheet**, and read the suggested amounts. Confirm them, check each line, and send the run for review.
3. **Approve it.** An Approver approves the run, as for a real one.
4. **Make the payment list.** Open the run and choose **Download Remitly list**. On a test run the bank details are masked and every row says **TEST - do not pay**, so the file cannot be used to pay anyone by mistake. Record a reference for each person to try **Mark paid**: nothing is sent anywhere.
5. **Read the statements.** Open **Payroll**, then **Statements**, and open the run. Read each contractor's statement or download them all as one PDF. They are stamped **TEST**. The **Release to everyone** button is off for a test run: a contractor never sees it.
6. **Make the invoice.** Open **Invoices**, then **New invoice**, choose the test run and the client. The invoice is numbered **TEST** and stamped **TEST** on the page and the PDF. Do not send it.
7. **Tidy up.** Open the run, choose **Run options**, then **Archive this test run**, and give a reason. Archive the TEST invoice from **Invoice options**. Both stay on record and you can restore them. When you are sure you do not need the practice any more, open the **Archived** view on the Payroll page, tick the runs, choose **Bulk actions**, **Delete for good**, and **Apply** (and do the same for the test invoices on the Invoices page). This cannot be undone.

# To repeat a cycle you already ran for real

If you ran a period for real and want to practise it again, open that run, choose **Run options**, **Mark as a test run** (this works until the run is paid), then **Archive this test run**. The period is then free for a new run. A real run that has been paid can never be marked as a test.

# Common mistakes

- **Dates that are not a whole cutoff are refused.** Only a test run can use other dates; tick **This is a test run** first.
- **The pay is a full cutoff although the dates are shorter.** A test run for part of a cutoff still works out a full cutoff of base pay. Enter the days worked as amounts if you want to see a partial one.
- **You can't release the statements.** That is on purpose for a test run. Only a real, approved run can be released.
