# App shell, dashboard and search

> Moved out of CLAUDE.md to keep that file short. These are the full working notes for this area: read them before changing it. The hard rules are repeated in CLAUDE.md's "Module notes" index.

## App shell

- `components/shell/app-shell.tsx` frames every signed-in page: the window never scrolls, the menu and header stay put and **only the content area scrolls** (`h-dvh overflow-hidden`; the root is `relative` so screen-reader-only text, which is absolutely positioned, cannot stretch the page). The shell and the menu use `overflow-clip`, **not** `overflow-hidden`: a hidden box can still be scrolled by the browser itself, and a screen-reader-only field (absolutely positioned against the shell, so far down a long page it makes the shell scrollable) that got focus pushed the header and the top of the menu out of sight until a refresh. A clipped box cannot scroll at all. `tests/e2e/shell.spec.ts` reproduces it by focusing such a field. Printing turns the clipping off. Anything that must scroll the page (a sticky element, `scrollTo`) now works against the content box, not the window.
- The desktop menu can be **narrowed to icons** (toggle button at the left of the header). It is a plain cookie (`elevate_sidebar`, name in `sidebar-cookie.ts`) read by the server layout so the right width renders at once. Do not import that constant from a `"use client"` file into a server file: the server gets a reference, not the string. Icon links keep their name for screen readers and a `title`. Test: `tests/e2e/shell.spec.ts`.

### Content width, tables, account menu, unsaved changes and the quick tour

- **Content width:** `main` has 16px side padding on a phone, 40px from the tablet width and 48px on a large screen; list and detail pages fill the width (no `max-w` cap on pages; narrow forms and reading pages keep `max-w-3xl` or less).
- **Tables** (any `table` inside `#main`, rules in `globals.css`): a tinted header and striped rows, light and dark. A row that sets its own colour still wins (the stripes are in the base layer). The `Table` component's container scrolls sideways with edge shadows (`.scroll-shadow-x`); a table sitting straight on the page passes `containerClassName="[--shadow-cover:var(--background)]"`.
- **Account menu** (`shell/account-menu.tsx`): the header shows the person's initials (`lib/initials.ts`) instead of the email; the menu holds My profile, My data, Quick tour and **Sign out, which asks first** (and warns if the person is still clocked in). The badge shows the person's **profile photo** when there is one (see below).
- **Profile photo** (`core.users.photo_path` / `photo_updated_at`, migration 0048; `people/photo.ts` pure, `photo-service.ts`, `photo-actions.ts`, routes `/api/profile-photo` (upload) and `/api/profile-photo/[userId]` (serve); permission `people.manage_photo`: everyone their own, HR and Super Admin can also remove anyone's). It lives on the **account**, so staff with no people record can have one too. The browser crops to a 320 px square JPEG (`profile-photo-dialog.tsx`: move and zoom in a round frame, so the original with its camera and location details never leaves the device); the server **re-checks the bytes, removes every APPn and comment segment** (`cleanProfilePhoto`, no image library needed) and stores only the cleaned copy in `employee-docs/avatars/<user id>/<random>.jpg` (a new name each time; the old file is removed). It is served by the app to any signed-in colleague (same audience as the directory), never as a public link; the address carries `?v=<time changed>` so a new photo shows at once. Audit: `profile.photo_set`, `profile.photo_remove` (no picture data). Changed from the account menu ("Add a photo") or My profile ("Change photo", via `OPEN_PHOTO_EVENT`). Tests: `people/photo.test.ts`, `tests/authz/photo-actions.test.ts`, `tests/integration/profile-photo.test.ts`, `tests/e2e/profile-photo.spec.ts`.
- **Unsaved changes** (`components/unsaved-changes.tsx`, provider in the shell): a form calls `useWarnWhenEdited(values)` (or `useUnsavedChanges(dirty)`) and, while it holds edits, clicking any internal link asks "Leave without saving?" and closing or reloading the tab asks too. The browser's Back button cannot be intercepted with client-side navigation. New forms with free text or many fields should use it.
- **Quick tour** (`shell/quick-tour.tsx`, steps in `tour-steps.ts`, `motion` for the animation): starts by itself for a new account (`core.users.onboarding_tour_seen_at` null; migration 0046 marked everyone who already existed as seen), replays from the account menu (`START_TOUR_EVENT`) and from Settings (`/dashboard?tour=1`, for every role). A step points at an element marked `data-tour="..."` and is skipped when that element is not on screen. Finishing or skipping calls `completeTour`. Test accounts made by `tests/e2e/helpers.ts` start with the tour already seen (`{ tour: true }` to test it).

## Dashboard and search

- `src/modules/dashboard/`; permissions `dashboard.view` and `search.use` (every role; they only open the door, each widget and search source applies its owner's own rule). **Widgets are server components, each in its own `Suspense`**, composed in `app/(app)/dashboard/page.tsx` by view. A widget a person has no access to comes back empty (`orFallback` turns a `ForbiddenError` into nothing); never put a permission rule in a widget that the owning module does not have.
- **Views (lenses)** (`lens.ts`): Admin, HR, Executive, My team, Hiring, My work, one per role a person holds (Super Admin gives Admin, HR, My team and Hiring, since it can do everything those roles can; "My work" is always there). **Super Admin is never behind HR Admin, Team Lead or Recruiter**: `tests/authz/matrix.test.ts` fails if any action gives it a narrower scope than one of those roles (Safe Voice cases, a person flag, are the exception). A person with several roles gets several tabs. **A view only changes which widgets come first and is never a permission**: the roles already combine (widest scope wins). Chosen by `?view=` or the `elevate_view` cookie, otherwise the first view held.
- **Widgets:** greeting and summary line; key numbers (`queries.ts` `getKpis`, live counts: people, onboarding, clocked in, approvals, jobs, applicants); quick actions (`quick-actions.ts`, shown only when `scopeFor` of the button's permission is not null); approval queue (`getApprovalQueue` in `feed-queries.ts`, merges time off, time corrections and extra hours; only items with `canDecide`); needs attention (`getAttention`, ranked, **counts and wording only, never a name or reason**); who is out this week (`weekAhead`, uses `getTeamCalendar`, so leave-type and name visibility follow the calendar's rules; anniversaries for HR and leads only, **no birthdays**); onboarding and offboarding tracker (`panel-queries.ts` `getTracker`, task progress from stored task status); workforce overview (nightly analytics tables, so small groups stay merged or hidden); early warnings (`risks.ts`).
- **Inline decisions** (`approval-row.tsx`) call the existing `decideRequest`, `decideCorrection` and `decideExtraHours`, so every rule and check of those pages applies. **Approve is offered inline only when there is nothing to inspect**: a correction or extra-hours request with screenshots (or one only HR may decide) shows "Review" and opens its page. Decline always asks for a reason.
- **Early warnings are about teams and operations, never one named person.** There is no per-person score and no "who might leave" guess (fairness and privacy; counsel would have to approve it first). Every card shows its rule ("Why you see this"). Rules: attendance rates up 3+ points over the 4 weeks before (rate 5%+, only complete weeks, every week visible), more people left than joined, a finished pay period with unapproved hours, a day with 5+ (or 5%) off, fewer applicants than open jobs, reviews past due. Hidden-for-small-groups cells are never guessed at.
- **Safe Voice is deliberately NOT on the dashboard** (no counts, no feed item): its in-app notice is hourly and batched so the time a report arrived cannot be read off a live counter.
- **Global search** (header box, Ctrl+K or ⌘K, `shell/global-search.tsx`, server action `search-actions.ts`, `search-service.ts`): pages are matched in the browser; people, applicants, equipment and announcements come from the server, each by its own rule (everyone: the directory's fields; HR and recruiters: applicants; HR: any equipment, others only theirs; announcements the person can read). Titles and links only, 2 to 60 characters, wildcard characters escaped, rate limit `search` (200 per 10 minutes). Nothing is stored or logged.
- Tests: `src/modules/dashboard/dashboard.test.ts` and `risks.test.ts` (pure), `tests/authz/dashboard-actions.test.ts` (every role), `tests/integration/dashboard.test.ts` (real Postgres: scope of anniversaries, tracker, applicants in search, wildcards), `tests/e2e/dashboard.spec.ts`.

## Pages split from Attendance, and paging rule

- **Own menu items** (each its own address, highlighted on its own): `/extra-hours` (everyone), `/team-attendance` (`attendance.view` all or team), `/hours-review` (`hours.approve` all or team, week by `?rweek=`), `/jibble` (`jibble.manage`), `/schedules`. Attendance keeps My time, Corrections, Hours export, Rules and Health. Old `/attendance?tab=team|extra|review|jibble` addresses (stored notifications, bookmarks) redirect to the new pages; new links and notifications use the new addresses.
- **Menu visibility:** `NavItem.access` (`src/lib/nav.ts`) hides an item from roles without one of the listed scopes (evaluated in `(app)/layout.tsx` with `scopeFor`, passed down as `hidden`). It only shortens the menu; pages and actions still authorize.
- **Every long list is paged** (default 25 rows; 10, 25, 50, 100 offered; card lists default to 10). Pure rules in `src/lib/pagination.ts` (`parsePaging`, `pageInfo`, `paginate`). Server-rendered lists use `PagerLinks` (`src/components/pager.tsx`; page and size live in the address, with their own parameter names when a page holds several lists, as on Team attendance). Lists already in the browser use `usePaged` and `ClientPager` (`src/components/client-pager.tsx`; going back to page 1 when the filter changes is done through the reset key). Schedules selection is kept across pages and "Select all N matching" covers every page. A new list of more than a handful of rows must use one of these.
