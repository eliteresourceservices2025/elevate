# ELEVATE Learn (HIPAA and other training)

## ELEVATE Learn: HIPAA and other training

- **Plan:** `docs/learn/` (start at `README.md`; seven documents covering decisions, architecture, data and security, course and exam, UX, testing and review, rollout). **Read it before touching `apps/learn` or adding `learn` tables.** Status: Releases 1 and 2 are built (HIPAA, Cybersecurity basics, course studio, client add-on courses); the sections below describe each part.
- **Shape:** `apps/learn` is its own Next.js app and Vercel project at `learn.eliteresourceservices.com` (port 3200 locally). People use their ELEVATE account through a **one-time POST handoff** (60-second single-use token stored hashed; Learn then keeps its own session). A shared cookie across the parent domain was rejected because it would reach Safe Voice. Learn has no Supabase keys and none of ELEVATE's secrets; ELEVATE owns the `learn` schema migrations and the HR pages, jobs and certificate sync (into `talent.credentials`).
- **Rules decided:** Full track (healthcare-client VAs) and Essentials track (internal staff); new hires within 30 days, renew every 12 months; modules in order with a server-measured minimum time; exam of **20 questions** for HIPAA (15 for Cybersecurity), **80% to pass, 3 tries**, graded on the server by a definer function so the answer key never reaches the app role; leads see only passed / not yet, scores belong to the person, HR and the designated Privacy Officer; results kept 6 years, per-question answers 12 months; no patient data, no proctoring, no pay or hours computed from training time; overdue warns, never blocks.
- **Constants** are in `apps/learn/src/lib/constants.ts` (with a test that keeps the agreed values).
- **Course and player (built):** the 10 HIPAA modules of version 2 (about 125 minutes; keys `foundations`, `phi`, `privacy`, `rights`, `associates`, `security`, `incidents`, `enforcement`, `lab_public`, `lab_records`; Essentials = foundations, phi, privacy, associates, incidents, lab_public; Refresher = foundations, phi, privacy, incidents) and the bank of about 200 questions, **HIPAA only** (plan and gap map in `docs/learn/12-deepening-plan.md`; lesson blocks now also include table, layers, timeline, glossary and worked case) (every factual claim is traced to HHS or the regulation in `docs/learn/08-source-check.md`; re-run that check when the content or the rules change). **Exam: 20 questions (HIPAA), 80% to pass, 3 tries, no time limit, all tracks** (migration 0056: `deadline_at` is null when the exam configuration has no `minutes`; the limit still works when a course sets one). General cybersecurity basics are a separate course (`apps/learn/src/content/cybersecurity`, slug `cybersecurity`, 10 modules in version 2, about 112 minutes and a bank of about 160 questions (exam 15): why, passwords, phishing, malware, browsing, ai_tools, devices, physical, response, security_hipaa; sources in `docs/learn/09-cybersecurity-sources.md`): the registry `apps/learn/src/content/index.ts` lists every course, `pnpm learn:publish --course <slug>` and `pnpm learn:assign --course <slug>` select one are authored in `apps/learn/src/content/hipaa/` (`m1`..`m10`, `q()` builds options and key), validated by `content/schema.ts` and linted by `content.test.ts` (unique stems, a real key, no markup, no real-looking identifiers or addresses, knowledge checks never reused as exam questions). **Content is data, not HTML**; knowledge checks and scenarios carry their feedback (not graded), exam questions live only in `learn.questions`. `apps/elevate/src/modules/learn/publish.ts` (`loadCourse`, `assignCourse`; scripts `pnpm learn:publish` and `pnpm learn:assign`) writes it to the database: a new version is a DRAFT, saving the same content again changes nothing, and **publishing needs `--reviewer <email>` and `--counsel-date`** (the launch gate; publishing freezes it). Use `tx.json()` for jsonb (a string cast to `::jsonb` is double-encoded). Learn serves it from the database: pages `/`, `/course/[assignmentId]`, `/course/[assignmentId]/[moduleKey]` (`ModulePlayer`: marks each screen opened, a heartbeat every 30 s only while visible and active, idle prompt after 5 min, Finish needs every screen and the server-credited time), `/exam/[attemptId]` (`ExamRunner`: answers saved as chosen, server deadline, results with a review only after a pass), `/certificate/[assignmentId]` (attestation, then a printable certificate), `/verify` (public; reference AND name). Calls are POST `/api/<action>` (`apps/learn/src/lib/api.ts`: screen, time, complete, startExam, answer, submit, accept; same-site only, session required, one database function per call, friendly messages for `learn:<code>` errors) and `/api/verify`. **Reads through row-level security must run inside `withUser`**; a bare query returns nothing. Tests: `tests/integration/learn-course.test.ts` (publish gate, assigning, a whole course through the real handlers, key never in a response, failed try shows topics only, wrong person or site refused) and `tests/e2e/learn-course.spec.ts` (needs both dev servers).
- **Database (migration 0054, applied before any Learn deploy):** schema `learn`, 17 tables with RLS, role `learn_app` (NOLOGIN; ops sets the password out of band). The app role has **SELECT only** (own rows via RLS keyed on `set_config('learn.user_id', ..., true)` per transaction; the question text but **never `correct_ids` or `rationale`**) and writes only through `SECURITY DEFINER` functions (`open_screen`, `credit_time`, `complete_module`, `start_exam`, `save_answer`, `grade_attempt`, `attempt_review`, `accept_and_certify`, `verify_certificate`, `consume_launch_token`, `create_session`, `resolve_session`, `end_session`) that hold the rules (module order, screens, server-credited time, tries, wait, deadline, name match). EXECUTE is revoked from PUBLIC for every function in the schema: **a new function must be granted to `learn_app` on purpose**. Published versions, their modules and questions are frozen by triggers; progress, attestations, certificates, revocations and retry grants are append-only; time only grows. ELEVATE reads `learn.v_status` (no scores) for leads. `drizzle.config.ts` `schemaFilter` now includes `learn`.
- **ELEVATE side (built, migration 0055):** `src/modules/learn/` (`rules.ts` pure and tested: track, due date, renewal, reminder thresholds, ISO week; `jobs.ts`; `queries.ts`; `actions.ts`; `validators.ts`; `constants.ts`). **Jobs** (registered in `src/inngest/functions.ts` and `health/registry.ts`): `learn-assign` (daily 1:35 AM Phoenix: everyone with an account and an active people record who has no open assignment and no current certificate gets one: new hire due 30 days from start, long-time staff 30 days from today, renewal on the Refresher track when a certificate ends within 60 days; open assignments of people who left or whose account closed are cancelled; passed assignments whose certificate ended become expired; does nothing until a version is published), `learn-remind` (daily 8:50 AM Manila: in-app notice at 30 days, 7 days and the due date, each once via `learn.reminders`; once a week the overdue people are listed to their lead and HR as one count), `learn-sync` (every 30 minutes: a Learn certificate is recorded in `talent.credentials` with source `learn`, once via `learn.certificate_sync`; a revocation archives it; the same step queues one email with the certificate PDF attached, `learn-certificate:<id>` dedupe key, no scores), `learn-purge` (daily 3:50 AM: finished tokens and sessions, and exam answers 12 months after submission, only through the job: the database guard needs `learn.purge = 'on'`). Each takes an optional `{ userIds }` scope for tests and one-off runs. **Track:** Full if the person has an active assignment to a client with `core.clients.handles_phi` (default on, set on People > Clients), otherwise Essentials. **Training status page** (`/training`, `learn.view_status`: HR and Super Admin all, Team Lead their downline): passed, not yet, overdue, not assigned; HR also sees tries and the latest score and can assign a track or give more tries or exam time with a reason (`learn.assign`, `learn.grant_retry`; nobody grants their own; audited; the person is notified). A lead sees status only. Team scope is checked with `scopeFor` and the downline, not `authorize` (a list has no single resource). Tests: `src/modules/learn/rules.test.ts`, `tests/authz/learn-actions.test.ts`, `tests/integration/learn-jobs.test.ts`, `tests/e2e/learn-training.spec.ts`. **An array passed to a drizzle `sql` template is expanded into a list**: pass a Postgres array literal (`uuidArray()`).
- **Two courses are assigned and reported** (`src/modules/learn/constants.ts` `LEARN_COURSES`: `hipaa`, and `cybersecurity` with one `full` track, so a renewal repeats the course). `runLearnAssign(today, scope, courseSlug)` runs once per course in the nightly job (each does nothing until that course is published; everyone active gets Cybersecurity basics). Training status has a course tab (`?course=cybersecurity`) and the assign action takes a `course`; notices name the course. Certificate references: `ERSHC-` (HIPAA), `ERSCSC-` (Cybersecurity), `ERSLN-` (other), old `HC-` valid (migration 0058). Sample certificates (invented name) are in `docs/learn/samples/`. **Menu:** "My training" (`/learn`) and "Training status" are under Learning; **Privacy incidents and Contact support sit in the Speak up group** with the anonymous Safe Voice link.
- **Course studio** (`/course-studio`, `/course-studio/<course>`, `/<version>`, `/<version>/m/<module>`, `/<version>/questions`, `/<course>/diff?from=&to=`; permission `learn.manage_content`: HR and Super Admin, and the Privacy Officer through the flag; menu item "Course studio" in Learning; migration 0063): read every version, **diff** two versions (`studio-diff.ts`, questions matched by `learn.questions.lineage`, then by wording), and **edit a draft**: course title and responsibility statement, module settings (title, summary, minutes, tracks, key points), each screen's blocks (text, list items, callouts, compare, steps, scenarios, knowledge checks) and each exam question (wording, options, key, reason; the type and module stay). **Phase 3, structure:** add (scaffolded with "TO WRITE:" text, `studio-scaffold.ts`), remove and reorder modules and screens, add and remove blocks inside a screen, add and remove exam questions, and edit the exam rules (pass mark, tries, wait, certificate months, questions per track) through one general `editDraft` that rewrites content, rules, `version_modules` and the question rows in one transaction and must pass the checks (an exam track cannot be left with fewer questions than it draws). **Phase 4:** a publish checklist (`studio-checklist.ts`: required items are no check errors, no "TO WRITE:" text left, differs from the live version, saved last by someone else; advised: 8+ questions per module and a bank three times the exam length) which the server enforces again, and a **preview in Learn** (`/preview/<course>/<version>` and `.../<module>`, migration 0064: `learn.is_content_editor()` and a draft-read policy for HR, Super Admin and the Privacy Officer; nothing is recorded; the answer key is still ungranted). Still not built: previewing the exam, comments between editors, and changing a question's type or module. Rules: a **draft is a copy of the latest published version** (`createDraft`), one draft at a time; every save carries the draft's `edit_stamp` and a stale one is refused; every save must pass `lintCourse` (`studio-lint.ts`, the same rules as the code content tests: markup, number shapes, web addresses, key, duplicate wording, knowledge-check repeats; thin banks are warnings); `version_modules` are rebuilt from the content; a published version is frozen by the database triggers. **Publishing** (`publishStudioDraft`) needs a reviewer account, the counsel date, a change from the live version, no lint errors and **someone other than the last editor**; the old version is retired. The first draft marks the course `studio_managed`, after which **`pnpm learn:publish` refuses that course** (it would overwrite the studio's work). Audit: `learn.studio_draft`, `learn.studio_edit` (part, module, screen or question id), `learn.studio_publish`, `learn.studio_discard`: never the text. Tests: `studio.test.ts` (lint and diff), `tests/authz/studio-actions.test.ts`, `tests/integration/course-studio.test.ts` (its own test course).
- **Courses as data (client add-ons, step 1 of 4; migration 0065):** `learn.courses` gained `kind` (`core` | `client_addon`), `client_id`, `label`, `noun` and `fixed_track` (checks keep a client with an add-on and none with a core course). The two core courses are still listed in code (`constants.ts` `CORE_COURSES`: their lessons are code), and everything that loops over courses reads `listLearnCourses(db)` (`course-catalog.ts`: core first, then add-ons by name; `findLearnCourse`, `pickCourse`, `describeCourse`) instead of a fixed list: the nightly assignment, reminders, Training status tabs, the dashboard counts, validators (a course address is checked by shape, then looked up). `runLearnAssign` only handles core courses; add-ons are assigned by their client's people in a later step. No add-on exists yet, so behaviour is unchanged. Tests: `course-catalog.test.ts`, `tests/integration/learn-addons-catalog.test.ts`.
- **Creating a client add-on (step 2 of 4):** Course studio > "New client add-on" (`createStudioAddon`, `learn.manage_content`, `createClientAddon` in `studio-service.ts`, scaffold `newAddonCourse`/`addonSlugFor` in `studio-scaffold.ts`): pick an active client that has no add-on (one per client for now) and the studio makes a `client_addon` course (address `<client-name>-requirements`, label and noun "<name> requirements", fixed track `full`, studio-managed) with a version-1 draft: one module of three screens, five placeholder questions and an exam of 5 questions at 80%, 3 tries, 12 months. A client name that would trip the text checks (a web address) is used in titles only, never in lesson text. Everything after that is the existing studio (edit, checks, preview, publish by a second person); for an add-on the publish date field reads "Date the text was approved (by counsel or the client)". Nothing is assigned until it is published (and, from step 3, until its assignment rule exists). Audit `learn.studio_addon_create` (course address and client id, never text). Tests: `tests/integration/learn-addon-studio.test.ts`, `studio-structure.test.ts`, the authz studio matrix.
- **Assigning a client add-on (step 3 of 4):** `runLearnAssign` now handles add-ons (`addonClient` branch in `jobs.ts`; the pure rule is `addonNeed` in `rules.ts`). **Who:** people with an active people record and account who are currently assigned to the add-on's client (`core.client_assignments` with no end date) and have no open assignment and no current certificate; track `full`; due 30 days after they joined the client (the earliest start of their current assignments to it), or 30 days from today when they joined long ago; a renewal opens 60 days before the certificate ends and repeats the course. **Leaving the client:** an open assignment made by the job (`created_by` is null) is cancelled when the person has no current assignment to the client; one HR assigned by hand is kept; the certificate stays on record. **Pilot:** the first time a course is published from the studio (no earlier published or retired version) a `paused` row is written to `learn.assignment_rules` (audit `learn.studio_publish` has `startedPaused`), so nothing is assigned until HR chooses on Training status; the existing all/teams/paused choice applies to add-ons. **Training status** for an add-on lists only the client's current people (and anyone who has an assignment) and says so. **Client assignment form** (People > Clients tab, `getTrainingReadiness` now takes the `clientId` and also returns the client's live add-on) shows the add-on's status as a reminder next to the HIPAA line; assigning is never blocked. Tests: `tests/integration/learn-addon-assign.test.ts`, `addonNeed` in `rules.test.ts`.
- **Add-on records and reports (step 4 of 4; migration 0066):** certificates of a `client_addon` course get the reference `ERSCL-YYYY-XXXXXX` (`accept_and_certify` picks the prefix by course kind; the reference check accepts it; old references unchanged). The **client evidence report** gains the client's add-on as three CSV columns and one PDF column (`EvidenceReport.addon`, `EvidenceRow.addon`; only when the client has a live add-on; completion only, as before). The dashboard needs-attention counts and Training status tabs already come from the course catalog, so an add-on appears with its own label. The Learn certificate page no longer says "not an official HIPAA certification" (it reads "not an official certification from an outside body", true for every course), and the session-expired page says "training" instead of "HIPAA training". **Client add-ons are complete.** Open for later: several add-ons per client, a client column in the dashboard for many add-ons, and an acknowledgment-only add-on (no exam).
- **Client evidence report** (Training status > "Client evidence report", `learn.export_evidence` = HR and Super Admin, `exportClientEvidence`, `learn/evidence.ts` builds it and `evidence-format.ts` is the pure CSV, PDF and status rule): for a client and a date, everyone assigned that day with their HIPAA and Cybersecurity certificate status (valid, expired, revoked, trained later, none), reference and dates. **Completion only: no scores, tries, answers or IP addresses.** CSV cells go through `csvCell`; rate limit `download`; audited `learn.export_evidence` with client id, date, format and counts.
- **Client assignment readiness** (`people/actions.ts` `getTrainingReadiness`, `learn/certificate-status.ts` `trainingReadiness`): on a person's Clients tab, choosing a client that `handles_phi` shows their HIPAA status (passed and valid until, not yet or overdue, certificate ended, nothing yet). **A reminder only: assigning is never blocked by training** (decided with the owner). `people.manage_assignments`; no scores.
- **Dashboard training counts** (`getTrainingCounts` in `learn/queries.ts`, in the needs-attention list): per course, people with overdue training and certificates ending in the next 30 days with no renewal yet. - **Onboarding check `hipaa_training`** (migration 0062; `learn/certificate-status.ts` `hasCurrentCertificate`): a checklist task ticked by ELEVATE when the person holds a current (not ended, not revoked) HIPAA certificate. In the built-in onboarding list as "Complete your HIPAA training" (the person's task, due 30 days from the start, **not required**, so a pilot that has not assigned them yet never blocks completing onboarding); templates may use it for onboarding only.
- **My training record** (Learn `/record`, `getRecord` in `apps/learn/src/lib/queries.ts`, linked from the Learn home): the person's own assignments with version, track, status, dates, time spent, tries, their own passing score and certificate (reference, dates, PDF download), read through their own rows. It is also in **My data** (`training` section: dates, status, minutes, certificate reference; never answers or question text). A combined "my record" PDF is not built.
- **Reminder emails** (migration 0061: email kind `reminder`, priority 2 like the digest, and `ops.email_preferences.training_reminder_opt_out`, a checkbox on Settings > Email notifications): `runLearnReminders` queues one email with each in-app reminder (30 days, 7 days, due date) and a weekly one while overdue (the person is also told in the app, `learn.overdue_self`). Text carries the course name, the due date and a link to My training only: no scores, attempts or content. Deduped per assignment and threshold (`learn-reminder:<assignment>:<kind>`); a person who opted out still gets the in-app notice. They share the daily email budget (certificate copies and acknowledgments go first), so a first night with many assignments drains over a few days.
- **Pilot limit** (`learn.assignment_rules`, migration 0060, `setAutoAssign` / `getAutoAssign`, `learn.assign` = HR and Super Admin, card "Automatic assignment" on Training status per course tab): who the nightly job assigns a course to: `all` (no row = everyone, how courses worked before), `teams` (people whose current `team_id` is in the chosen teams; manual Assign still works for anyone) or `paused` (nobody; leavers are still closed out, expired certificates still marked, open assignments keep their reminders). **`pnpm learn:publish` inserts a `paused` row the FIRST time a course goes live** (not on re-publishing), so publishing alone assigns nobody until HR chooses. Audited `learn.auto_assign` (mode and team count). Only ELEVATE touches the table; `learn_app` has no grant.
- **Certificate PDF** (`apps/learn/src/lib/certificate-pdf.ts`, `pdf-lib`, A4 landscape): download at `/api/certificate/<assignment id>` (own certificate, `no-store`, revoked refused; logic in `certificate-download.ts`). **The same file lives in `apps/elevate/src/modules/learn/certificate-pdf.ts` for the emailed copy; a test fails if they differ, so change both together.** `pdf-lib` was added to `apps/learn` (same version ELEVATE and Safe Voice already use; needs the owner's OK, flagged). Email attachments can now be binary (`EmailAttachment.base64`).
- **Sign-in handoff (built):** ELEVATE page `/learn` (menu "HIPAA training", `?auto=1` starts by itself) -> server action `startLearnLaunch` (`learn.launch` for every role, rate limit `learnLaunch`, audit `learn.launch` with no token) -> `createLaunchToken` (`modules/learn/service.ts`: 256 random bits, only the SHA-256 stored, 60 s, sign-in methods from `currentSignInMethods`) -> the browser form-POSTs it to `<LEARN>/auth/handoff` (`NEXT_PUBLIC_LEARN_URL`, local default `http://localhost:3200`). Learn (`apps/learn/src/lib/handlers.ts`, testable with injected deps): `Origin` must equal ELEVATE's address, rate limit, then `consume_launch_token` + `create_session` in one transaction, cookie `__Host-learn_session` (HttpOnly, Secure, SameSite=Lax; `learn_session` without Secure in development), sessions looked up by hash (30 min idle, 8 h absolute, account must still be active). Failures all go to `/expired` (links to `/learn` without `auto`: no loop). No session on `/` redirects to ELEVATE `/learn?auto=1`. Sign out is POST `/auth/signout` (same-site only, judged by `Sec-Fetch-Site`, because `Referrer-Policy: no-referrer` makes browsers send `Origin: null`) and goes to `/signed-out`, which forwards to ELEVATE with a meta refresh. **Learned the hard way:** `form-action 'self'` also applies to the redirects of a form post, so a post can never be redirected straight to another site; and cookies are shared across ports on `localhost` (an e2e test must not clear them by host). There is **no session secret**. Tests: `apps/learn/src/lib/session-rules.test.ts`, `apps/elevate/src/modules/learn/token.test.ts`, `tests/authz/learn-actions.test.ts`, `tests/integration/learn-handoff.test.ts` (the real Learn handlers through the real `learn_app` role), `tests/e2e/learn-handoff.spec.ts` (needs both dev servers; `LEARN_URL` and `E2E_BASE_URL`). The two integration files set the cluster-wide `learn_app` password to the same fixed test value; a local Learn `.env.local` uses that value too.
