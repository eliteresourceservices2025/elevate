# ELEVATE Payroll Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the executives' payroll spreadsheet with a `payroll` module where chosen people prepare and approve each cutoff, with a permanent change history and payslips.

**Architecture:** A new module in `apps/elevate/src/modules/payroll/` with its own Postgres schema. Pay amounts are encrypted, so a pure calculator does the arithmetic in the app. Access comes from one per-person level on `core.users`, never from a role. Runs are frozen by database triggers once they leave draft.

**Tech Stack:** Next.js 16 server actions, Drizzle, Postgres triggers, `lib/crypto.ts`, `@react-pdf/renderer` through `renderOfferPdf`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-04-payroll-design.md`

## Global Constraints

Read `CLAUDE.md` and `apps/elevate/AGENTS.md` first. Paths are relative to `apps/elevate/` unless they start with `docs/`.

- Branch `feat/payroll` from `main`. Never push without the owner's OK.
- Before each commit: lint, typecheck, relevant tests, and a code review. Before the final task's commit, also `pnpm build` and check the built app.
- `git add` named paths only; the working tree holds unrelated untracked files.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Real names and pay figures never enter the repo, tests or a development database.
- No role grants payroll. Every action calls `requireUser()` first, then `authorize()` inside `runAction`; Zod validates every input on the server.
- All arithmetic on money uses `bigint` centavos, never floats. Amounts cross JSON as strings.
- Audit rows, notifications, email, logs and Sentry never carry an amount or reason.
- Copy says "extra hours", never "overtime", and never "PTO". Every payroll label comes from `payroll/constants.ts`.
- Nothing computes tax or government contributions, and nothing sends money.
- Every new table enables RLS with no public policies. Do not add a job more often than 30 minutes; this plan adds no scheduled job.
- Pages use `PageHeader`, `PageContainer`, `TabNav`, `FormDialog`, `EmptyState`, `Alert`, `PagerLinks` per `src/ui-conventions.test.ts`. Long lists use `<Table stack>`.

## Review Focus

Most likely first. Each has a test in the task noted.

1. **Overlapping or mid-cutoff rate rows:** a raise dated inside a period must never pay a line twice or silently pick the new rate. (Task 5)
2. **Pasted money:** `1,250.50` must parse, while `$50`, `1,25.0` or `1.255` must be refused rather than misread. (Task 4)
3. **Net pay below zero:** a loan bigger than gross must block sending for review, not submit a negative payment. (Task 6)
4. **Stale decisions:** an edit that lands while an approver has the page open must refuse the approval, and a removed approver must be refused on the next request. (Task 8)
5. **A person with no linked account:** payroll works and the own-line rules hold, with no payslip notification and no crash. (Tasks 6 and 10)
